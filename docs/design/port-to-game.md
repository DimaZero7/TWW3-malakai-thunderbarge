14.11.2026. Спецификация переноса страницы (`web/`, коммит `f561401`) в мод. Игра не запускалась, код не менялся.

Просьба автора: «Окей, теперь надо перетянуть всё это в игру».

Метки утверждений о движке:
- **[игра: источник]** — проверено прошлыми запусками;
- **[файлы]** — проверено сегодня по паку игры через инструменты проекта (`build.game_tables()`, `gamepack.entries`);
- **[предположение]** — не проверено.

Пусть к прогонам: `runs/` = `build/campaign/runs/`.

## 0. Итог

- **Переносится почти всё.** Логику страницы с самого начала писали как модуль мода (`barge_buildings.js`: «can become src/tww3_mtb_buildings.lua line for line»). Рисунок тоже уже сделан как вызовы `UIComponent` (`gameui.js`): `CreateComponent`, `Resize`, `SetDockOffset`, `SetState`, `SetImagePath`, `SetTooltipText`, `SetOpacity`.
- **Стройку ведёт движок, а экипаж и панель — наш Lua.** Заказ, отмена и снос идут командами игры. Цену, срок, очередь, очки развития, сохранение и ИИ игра даёт сама. Статусы, причины, новости и экипаж считает наш Lua.
- **Чего на странице нет и что придётся решить:**
  - **найм войск в армию.** На странице есть только карточки «Открывает найм»; вопрос В7;
  - **очки развития.** В дереве автора их нет, `gameData` ставит `dev: 0`; вопрос В2.
- **Что в игре так, как на странице, сделать нельзя или не доказано:**
  - перетаскивание дерева мышью;
  - видеоролики в окне отряда;
  - подсветка как CSS-фильтр (её заменяют состояния картинок);
  - Малакай у борта на 12-м месте;
  - «здоровье барки» и бонусы одной группе (перезарядка и урон), которые складываются от нескольких построек.

  Подробности в разделах 1 и 3.
- **Один источник правды.** JS-модели страницы записывают сценарии с ожидаемыми ответами. Тот же Lua мода прогоняется по ним без игры (Lua 5.1 через `lupa`, есть на машине) и должен дать те же ответы. Раздел 4.
- **Этапов 6, запусков игры 6–7.** Первый запуск — пробный: он отвечает на все неизвестные движка сразу. Раздел 5.

## 1. Что умеет страница и как это будет в игре

Категории:
- **мод** — уже есть в моде;
- **данные** — генерируется сборкой из `tree_design.json`;
- **Lua** — новый код логики;
- **макет** — наши `.twui.xml` и компоненты из Lua;
- **рисунок** — нужен арт или перенос PNG;
- **движок?** — не доказано, проверяется пробой (раздел 5, запуск 1);
- **нельзя** — в игре не делаем, есть замена.

## 2. Данные: от `tree_design.json` к таблицам мода

### 2.1 Конвейер

```
web/data/tree_design.json
  → node tools/tree_export.mjs (новый): tree_model.gameData + effects_model.complete
        + геометрия (cxRoutes, lineMarks) + карточки (newOnLevel, oneCardPerUnit, slotCards)
  → build/tree/tree_rows.json   (одна выгрузка; её же читает страница вместо своего расчёта)
  → py -3.14 tools/build.py → tools/crew_buildings.py (расширить) → таблицы, .loc, значки
  → тот же JSON вставляется в Lua как CONFIG (как сейчас --@CONFIG@)
```

- **Почему через JS.** Правила линеек, наследования, «нового на уровне» и маршрутов линий живут только в `tree_model.mjs`. Их переписывание на Python было бы вторым источником. Node 20 на машине есть.
- **Python только пишет строки.** Новых правил в нём нет.

### 2.3 Ключи

**Рекомендация:**
- корпус — ванильные ключи `wh3_dlc25_dwarf_spirit_of_grungni_airship_hull_1..5`. Иначе нельзя: основной слот, `startpos`, цель победы `hull_4`, задание `hull_2/3`, выдача барки модом;
- `support_radius_1/2` — ванильные ключи. Скрипт игры `wh3_dlc25_spirit_of_grungni.lua` ставит зону влияния по этим ключам **[файлы, ранее: `panel-upgrades-proposal.md` §3]**;
- **всё остальное — новые ключи** `wh3_dlc25_dwarf_spirit_of_grungni_mtb_<id узла>` и новые цепочки `mtb_<первый узел линейки>`. Префикс тот же, что у пяти цепочек мода сейчас.

**Почему не переиспользовать ванильные `beer_hall_*` и прочие, как в моде сейчас:**
- **эффекты.** Удалить строку ванильной таблицы модом нельзя, только перекрыть по ключу **[предположение, общеизвестно; мод так и обнуляет вызов, 6 строк **[игра]**]**;
- **отряды.** Строки `building_units_allowed` у ванильных уровней останутся. При стоковом найме откроются отряды, которых в дереве нет (В7);
- **смысл ключей.** У `mtb_guns_3` и `mtb_nest_2` в дереве уже другой смысл, чем в моде («Палата органных орудий» против огненной пушки).

Ванильные боковые цепочки остаются в наборе орды для ИИ; игрок их не видит (В3).

**Сейвы.** Новая кампания обязательна — это уже правило мода (`summary.md` §8). Текущая игровая кампания автора с модом после переноса не загрузится как раньше: ключи цепочек сменятся. Сказать автору до выпуска пака.

## 3. Экран в игре: устройство

### 3.1 Принципы

- **Всё своё.** Свои макеты (`ui/tww3_mtb/*.twui.xml`) и компоненты из Lua; картинки игры берутся по путям в паке.
  - Шаблоны игры с привязками (`building_frame`, `land_unit_card`, `unit_information`, `building_information`) **не создавать**. Их списки берут данные из контекста браузера построек: `UnitList(Buildings.StoredSettlementOrCharacter, …)` **[файлы]**. Вне браузера этот контекст не задан.
  - Опыт на пробу: `CreateComponent` с `ui/templates/building_frame` и `uic:SetContextObject(cco(...))`. Метод есть в скриптах игры, в бою **[файлы: `lib_battle_script_unit.lua`]**. Если заработает, это даром даст настоящую рамку с ходами, но план на это не опирается.
- **Без обхода чужих детей.** Не обходить детей интерфейса игры циклами `ChildCount` / `Find`: это ломает привязки игры до перезапуска **[игра: `runs/20261104-191037`]**.
  - Чужие компоненты искать только `find_uicomponent` по пути.
  - На свои — держать ссылки в таблице Lua.
  - Закрытие: `Destroy` корня.
- **Единицы.** Единица страницы = единица интерфейса игры. Корень при 2560×1440 и UI 1,6 — 1600×900 (так на странице «Как в игре»). Размер панели берётся от `core:get_ui_root()`, формула `min(W − 40, 1560) × min(H − 30, 870)`, как в `panel.js`. Корень при 1080p и 4K не проверен: вопрос из памяти, решается снимками пробы.
- **Одна таблица стилей текста.** `TEXT` в `gameui.js`: шрифт, кегль, цвет, выравнивание. Вынести в `data/ui_text_layouts.json`. Читают и страница, и генератор макетов, иначе кегли разойдутся. Кириллица в категориях шрифтов игры работает **[игра: старая панель]**.

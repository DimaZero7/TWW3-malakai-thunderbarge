# Модульный экипаж барки

Состояние на 03.11.2026. Разбор сделан по `Warhammer3.exe` (SHA-256 совпал с установленным, `9bd58c63…`), `db.pack`, `anim2.pack`, `warmachines.pack` и README memreader Plus 0.15.1, затем проверен в игре: см. «Результаты опытов». Варианты и числа: [barge-loadout.md](barge-loadout.md).

Метки: **[код]** прочитано в exe, **[база]** строки таблиц, **[файлы]** файлы игры, **[README]** документация memreader, **вывод** заключение без проверки в игре, **[игра]** проверено в игре.

## Вывод

**Один отряд, 29 мест, в памяти меняется только один указатель на место.**

1. В `battle_personalities` заранее лежат обычные строки: одна на пару «место × вариант», это около 130 строк. Они строятся генератором из конфига и растут линейно.
2. В записи нашего отряда в памяти есть список мест. Перед боем Lua кампании пишет в каждое место указатель на строку выбранного варианта.
3. Игра читает этот список при создании каждого бойца, и модель, анимация и оружие берутся из строки.
4. Пустой отсек — это строка-невидимка. Такая есть в ванили, поэтому бойцов всегда 29 и ничего больше не пересчитывается.

Это лучше исходной идеи править поля строк: строки не меняются, запись атомарна, чужие отряды не задеты.

**Подтверждено в игре и сделано в моде:** все варианты всех отсеков, полный цикл с сейвом и загрузкой, отказ без memreader Plus. Нет интерфейса и построек, это решение пользователя; не убрана фигура у носа.

## Что сделано в моде

Штатный отряд `mtb_dwf_cha_malakai_thunderbarge`, новая кампания, настоящие бои кампании. Интерфейса и построек нет: выбор задаётся командой.

| Что | Где |
|---|---|
| Варианты, по записи на вариант | `data/crew_options.json` |
| Строки, модели, модуль Lua в пак | `tools/crew_options.py`, вызывается из `tools/build.py` |
| Запись мест, сохранение выбора | `src/tww3_mtb_crew.lua` |
| Команда выбора | `tww3_mtb_crew.set("rifles", "quarrellers")`, `tww3_mtb_crew.get()`, `tww3_mtb_crew.status` |
| Повтор полного цикла | `py -3.14 tools/crew_cycle.py all`, итог `py -3.14 tools/crew_cycle.py report` |

**Новый вариант = одна запись** в `data/crew_options.json`. Отрядов не прибавляется, строки на все места группы строит генератор.

### Полный цикл

Новая кампания → выбор → бой → автобой → сохранение → загрузка → другой выбор → бой. **После загрузки выбор восстанавливается:** в `a_new` выбраны пираты, в `b_load` сразу после загрузки `rifles=pirates`; так же в следующих сессиях.

### Безопасность

| Случай | Что произошло | Доказательство |
|---|---|---|
| memreader Plus не подключён | Кампания грузится, сообщение игроку, причина один раз в логе. Барка со стоковым экипажем при сохранённом выборе «всё пусто», 66 убитых | `cycle_f_no_memreader/no_memreader_map.png`, `no_memreader_right.png` |
| Шаблон не найден (как после патча) | Статус `stock: database pattern matched 0 times`, запись одна при трёх вызовах, кампания работает | `cycle_g_bad_pattern` |
| 1000 вызовов подряд | Lua 35 104 → 33 364 КБ, процесс 7081 → 7055 МБ, 0,1 с | `cycle_j_stress` |
| Много боёв в сессии | Память после боя 7414–7777 МБ за 5 боёв `d_cannons`, роста нет | `results.jsonl` |

Пишем только в список мест нашего отряда. Код игры не правится, в памяти игры ничего не выделяется.

**Откат после отказа не проверен.** Если шаблон перестал находиться уже после записи, места остаются последними записанными до выхода из игры. Запись всё равно не повредит: строки живы, а шаблон не может пропасть посреди сессии.

### Пустая барка под ИИ

Стояла в `cycle_h_ai_empty` и `cycle_i_ai_stock` из-за условий теста, а не из-за отряда. Армия ИИ с пушкой ждёт, пока игрок стоит на месте. Стоковые барки без мода в том же сценарии ведут себя так же.

| Прогон | Пушка у ИИ | Барка за 90 с, игрок стоит |
|---|---|---|
| С модом, полный экипаж | да | 0 м; пошла, когда игрок двинулся: 171 м, 201 убитый |
| С модом, полный экипаж | нет | 255 м, 166 убитых |
| С модом, пустой экипаж | нет | 148 м, 0 убитых |
| Без мода, стоковые | да | 0 м; потом 228–234 м |
| Без мода, стоковые | нет | 230–254 м |

Правка не нужна. Механизм ожидания выведен из опытов, код ИИ не читался. Подробности: [barge-behaviour-checks.md](../research/barge-behaviour-checks.md).

### Два исхода ночных вопросов

- **Отряд не двигался в первом бою:** ошибка теста, не игры. Приказ `attack_unit` по цели в 455 м не выполняется. С подлётом через `goto_location`, а затем `attack_unit` отряд долетает всегда. Исправлено в `C.order()`; подтверждено: `empty` и все бои выше, минимальное расстояние 0–13 м.
- **Фигура у носа:** не убрана. Источник найден, но замена файлов анимации из мода не действует. Подробности в журнале ниже, вопрос в `docs/questions-for-user.md`.

## Что выяснено в коде

### Как места попадают в бой

| Что | Факт | Метка |
|---|---|---|
| Сборка списка | При загрузке базы (один раз) строки `land_units_to_battle_personalities_junctions` раскладываются по записям `land_units`. `autonomous_rider` уходит в отдельный вектор записи отряда. **Поправка после игры:** первый статический разбор указал не на тот вектор (тот для `articulation_entity`), правильный нашёлся чтением памяти | [код], [игра] |
| Элемент вектора | Указатель на строку `battle_personalities`, указатель на имя точки крепления, номер сочленения, флаг. Значит, точка крепления **не хранится в строке места** | [код] |
| Вместимость | После сборки вектор ужат до размера: заменять можно, расти нельзя | [код] |
| Создание бойцов | При создании отряда в бою та же функция, что создаёт обычных бойцов, раздаёт им элементы вектора по очереди. Запись отряда берётся из строки `main_units` | [код], [игра] |
| Анимация | Имя таблицы лежит **строкой внутри** строки места и ищется по имени при создании бойца. Если таблицы нет, подставляется таблица `empty` | [код] |
| Сущность, масштаб | Читаются при создании бойца | [код] |
| Модель | Боец хранит указатель на элемент вектора. Путь `.variantmeshdefinition` собирается из строки варианта при создании вида бойца | [код] |
| Оружие | **Читается на лету всё время боя**: боец → элемент → строка места → `battle_entity_stats` → оружие | [код] |
| Копии | Не нашёл ни копии `land_units`, ни копии мест на бой. Менеджер анимаций глобальный. README: добавленные строки живут и при смене режима игры | [код], [README] |
| База одна | Путь создания базы один; бой обращается к тому же объекту. Что она не пересоздаётся при смене режима, следует из README | [код], вывод |

Ответы на вопросы задания:

- **Когда читается:** при создании каждого отряда в бою, плюс оружие во время боя. Не при старте игры и не один раз на сессию. [код]
- **Сработает ли запись из Lua кампании:** да. [игра]
- **Из скрипта боя:** не определил, идут ли скрипты боя раньше создания отрядов. Он и не нужен.
- **Менять между двумя боями:** да, в одной сессии. [игра] Кэш файлов не мешает, потому что другой вариант — это другая строка и другие файлы, а не те же файлы с новым содержимым.
- **Менять в бою нельзя:** бойцы держат указатели на элементы, а оружие читается на лету. Запись в бою сменит оружие без смены модели.

### Доступ к таблицам

`DATABASE_TABLE`: строки по смещению `+0x08`, карта ключей `+0x28`, имя `+0x58` [README]. Список таблиц находится по двум шаблонам кода, образец — `find_projectiles` в `tests/ingame_smoke.lua` репозитория memreader Plus. Смещение флага «база загружена» в этом тесте отличается от нашего exe: **смещения уже менялись между сборками**, поэтому такой флаг не зашиваем, а проверяем, что в таблице есть строки.

Адреса и смещения для работы лежат в `build/modular_crew/sites.json` (вне git).

## Архитектура

### Поток

```text
Постройка завершена, навык, награда            ProgressSource
        ↓  MilitaryForceBuildingCompleteEvent и другие события
Lua: unlocked[отсек][вариант] = true           только растёт
        ↓  новый вариант выбирается автоматически, игрок может сменить
Панель барки: selected[отсек] = вариант        смена в любой ход
        ↓  cm:set_saved_value: сейв хранит и то, и другое
apply(): для каждого из 29 мест
         вектор[место].personality = строка(место, selected)
        ↓  первый тик кампании, смена выбора, конфедерация
Запись отряда в памяти                         живёт до выхода из игры
        ↓  загрузка боя
Игра создаёт 29 бойцов из строк                модель, анимация, оружие, невидимка
```

В скрипте боя ничего не нужно. Проба боя нужна только для тестов.

### Прогрессия и выбор

| Что | Где | Правила |
|---|---|---|
| **Открытое** | `cm:set_saved_value("mtb_crew_unlocked", …)`: отсек → набор вариантов | Только растёт. Снос постройки не отнимает вариант |
| **Выбранное** | `cm:set_saved_value("mtb_crew_selected", …)`: отсек → вариант | Один вариант на отсек. Значение проверяется по открытому |
| **Старт** | Все отсеки `empty`. Открыт только `empty` | Новая игра и смена фракции |
| **Открытие** | Таблица `unlock` в конфиге: источник → (отсек, вариант). Источники: уровень постройки, навык, задание, ритуал | Lua проверяет полный список на первом тике, поэтому пропущенное событие не потеряется |
| **Смена выбора** | **Да.** Панель: ряд на отсек, в нём все открытые варианты. Ход не тратится | Применяется сразу в память, действует со следующего боя |
| **ИИ** | Лучший открытый вариант по порядку в конфиге | Отсчёт по рангу или ходу, а не по постройкам |

**Постройки.** Предлагаю пять цепочек на вкладке барки, по одной на отсек; каждый уровень открывает следующий вариант. Цепочка линейна, поэтому постройка хорошо подходит для открытия, но плохо для выбора. Смена вернулась бы к сносу, поэтому выбор отделён.

**Панель.** Минимум для первой версии — кнопка на отсек, перебирающая открытые варианты, с подсказкой. `twui.edit` memreader или свой компонент; сколько ячеек выдержит вкладка, не проверял (`docs/tools-and-work-plan.md`, этап 2).

Что выходит:

| Таблица | Строк | Откуда |
|---|---:|---|
| `battle_personalities` | около 130 | Места × непустые варианты: 72 + 8 + 4 + 8 + 7 = 99, плюс пустые на каждое из 27 мест и 2 постоянных |

Правила генератора:

- **Строка на пару «место × вариант».** Одна строка на вариант для всех мест могла бы работать: точка крепления хранится в элементе вектора. Но в ванили нет ни одного отряда, где одна строка занимает два места (0 из 1466 мест), поэтому лучше без риска.
- **Новый вариант** = одна запись и подготовленная модель, если модель своя. Отрядов не прибавляется.
- **Стоковые stats не менять:** эффекты ванили вроде огненных выстрелов пушки срабатывают по указателю на stats (см. раздел про эффекты).

### Lua

```text
apply():
    land_unit = строка наш_отряд в land_units
    проверить: размер вектора 29, каждый указатель — строка из battle_personalities,
               имена точек крепления совпали с конфигом
    иначе: записать в лог, ничего не менять, показать сообщение
    для каждого места: вектор[i].personality = строка(место, selected[отсек])
```

- Вызов: первый тик кампании (память могла сохранить состояние другого сейва), смена выбора, `FactionJoinsConfederation`.
- `apply()` повторяем, поэтому запись можно делать без сохранения прежнего значения.
- Фронтенд сбрасывает на стоковый экипаж, чтобы своя битва не получила выбор из кампании.
- Если memreader Plus нет или проверка не прошла: стоковый экипаж и сообщение. Поэтому начальное значение строк стоковое, а не пустое.

### Пустой отсек

Строка как `wh3_dlc23_chd_veh_hidden_rider`: `dummy_variant`, `default_skeleton`, без stats. В ванили 31 строка с `dummy_variant`, из них 17 даже стреляют (пушки Железного демона, молнии Doomwheel) [база]. Бойцов остаётся 29: `num_men`, вектор и размер отряда не меняются.

Ниши в корпусе остаются: это отложенный Kitbash из `barge-loadout.md`.

**Сокращать вектор не нужно.** В коде бойцы создаются по числу из данных отряда, а места раздаются первым из них: при меньшем векторе остальные, скорее всего, станут обычными бойцами без места [код, вывод]. Невидимки работают, поэтому E3b не проводился.

Цена невидимок мала: каждое место добавляет 8 здоровья при корпусе 12 348, разница между полным и пустым отрядом 1,7 % (`docs/research/weapon-variants-test.md`). Пустой экипаж в моём опыте дал те же 12 580, так как 29 мест на месте.

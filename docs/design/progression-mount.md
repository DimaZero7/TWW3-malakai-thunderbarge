# Малакай: стоковые навыки, пустая вкладка, барка как транспорт

Проверка осуществимости, 03.11.2026. Сделано и проверено позже: результаты в [progression-proposal.md](progression-proposal.md). Здесь остаётся разбор того, что было до реализации.

Метки: **[игра]** проверено в запуске, **[данные]** прочитано в таблицах, скриптах, интерфейсе или `startpos.esf`, **вывод** заключение без проверки.

Запуск: `build/campaign/runs/20261103-143152-prog1`, 389 с, сейв `tww3_mtb_crew_a.save`, текущий пак, 1280 × 720, `--igpu`. Игра закрыта, сейвы пользователя совпали по SHA-256.

## Итог

- **Транспорт уже есть в игре.** На вкладке «Подробности» есть блок «Транспорт» со списком: барка или «Без транспорта». Кнопка и скрипт для переключения не нужны.
- **Совсем пустая вкладка невозможна.** Боковые постройки убираются сразу, а основная снова появляется сама.
- **Рекомендация:** `airship_hull_1` становится пустым стапелем без вызова, а «главной постройкой» становится `airship_hull_2`.

## Решения пользователя

Эти вопросы закрыты.

1. **Вызов заблокирован и пешком, и верхом** в обычных боях кампании. Легендарные битвы стоковые. Шесть обнулённых строк остаются как есть.
2. **Главная постройка даёт саму барку с пустым экипажем:** только Малакай и труба (`fixed_seats`: `ap_captain`, `ap_thunderburner`).
3. **Экипаж расширяется другими постройками,** скорее всего «зелёными» цепочками. Какими именно, пользователь решит позже. Ниже только описание, таблицы привязки нет.

## 1. Как меняется транспорт в ванили

**[данные]**

- В `character_details_panel_details.twui.xml` есть блок `mounts_new`. Он виден, если у фракции есть транспорт, доступный этому персонажу или уже надетый на него.
- Строка `entry_none` вызывает `RemoveAncillary`. Строка транспорта вызывает `EquipToCharacter`.
- Все 774 предмета категории `mount` имеют `transferrable` = false и `turns_before_swap_allowed` = 0. Значит, смена работает и при таких значениях.
- Привязки к конкретному лорду в этом блоке нет. Есть только `CanCharacterEquip` и условие `CanUseArmoryItems == false`.
- У ванильных предметов 773 строки в `ancillaries_required_skills`, поэтому их открывают навыки. У нашего предмета такой строки нет. Наш предмет уже виден в списке, это есть и на старом снимке `20261102-212909-skills2/sk_panel.png`.

**[игра]** Три смены подряд кликами по списку, один ход, лорд не двигался:

| Состояние | Отряд | Здоровье отряда | Ранг | Навыки | Предметы в списке персонажа |
|---|---|---:|---:|---|---:|
| Верхом | `mtb_dwf_cha_malakai_thunderbarge` | 62,71 % | 4 | те же | 3 |
| Без транспорта | `wh3_dlc25_dwf_cha_malakai_makaisson` | 62,71 % | 4 | те же | 2 |
| Снова верхом | `mtb_dwf_cha_malakai_thunderbarge` | 62,70 % | 4 | те же | 3 |
| Снова без транспорта | `wh3_dlc25_dwf_cha_malakai_makaisson` | | | | |

- Снятый предмет уходит в резерв фракции: `has_ancillary` = false, `ancillary_exists` = true. В списке он снова доступен (`p4_dropdown_on_foot.png`).
- Панель пешком показывает стоковые числа, например здоровье 2897 при 62,7 %.
- Запас хода после смены 100 %.
- Содержание армии пешком 1387, на барке 1087.

**Чего это не показывает:**

- В игре есть текст `can_change_mount_once_per_turn`: «Менять транспорт можно только один раз за ход». Ограничение не сработало: три смены за ход прошли. После движения лорда смену не пробовал.
- Бой после смены через список не запускал. Пеший отряд стоковый, отряд на барке проверен раньше.
- Опыт в этом запуске не сравнивал, только ранг.

**Ловушка, [игра].** Текущий `src/tww3_mtb_campaign.lua` сажает Малакая обратно каждый ход. Он проверяет `has_ancillary` и выдаёт новый предмет, поэтому в резерве оказалось два одинаковых. Проверку нужно заменить на сохранённый флаг и `ancillary_exists`. Убрать оба экземпляра можно через `cm:force_remove_ancillary_from_faction` **[игра]**.

**Значок.** Тип предмета скопирован у Икита, поэтому и значок может быть от его транспорта (**вывод**, `ancillary_types.ui_icon` = `mount_doom_wheel.png`). Нужна своя строка типа и картинка.

## 2. Почему нельзя начать с нуля

**Откуда берутся стартовые постройки.** **[данные]** Из `startpos.esf` кампании `wh3_main_combi`, не из скрипта. В распакованном файле у войска `MALAKAI_BOUND_HORDE` записаны `airship_hull_1` и `barracks_1`. **[игра]** В сейве те же две постройки.

**Что проверено** **[игра]**:

| Способ | Результат |
|---|---|
| Команда удаления постройки войска в Lua | Нет такой: в списке команд `Warhammer3.exe` есть `add_building_to_force`, удаления нет **[данные]** |
| `Dismantle` для корпуса | `CanDismantle` = false, окна действий нет |
| `Dismantle` для `barracks_1` | Команда принята, `IsDismantling` = true. На следующем ходу всё ещё шёл снос. Возврат 1200 золота в интерфейсе |
| `cm:convert_force_to_type(mf, "ARMY")` и обратно | Работает мгновенно, см. ниже |
| Та же команда с числовым CQI | Ошибки нет и действия нет |

**Двойное преобразование:**

- боковые постройки исчезают сразу: `barracks_1` и добавленный для проверки `beer_hall_1`;
- **корпус появляется сам**, слот 0 снова `airship_hull_1`;
- сохраняются CQI войска 76, отряды, их состояние, ранг, предмет, запас хода, стойка;
- очки развития сбрасываются (1 → 0).

Преобразование разрешено таблицей `military_force_type_conversions`.

**Вывод:** основной слот орды пустым не бывает. Интерфейс для пустого основного слота я не видел.

**Другие пути и почему они хуже:**

- Свой `startpos.esf`: файл 9 МБ, ломается при патчах, конфликтует с другими модами. И основной слот всё равно может заполниться сам.
- Снос `barracks_1`: идёт дольше хода, в это время постройка видна, деньги возвращаются.
- `visible_in_ui` = false у `airship_hull_1`: не проверял. Это единственный путь к виду совсем пустой вкладки. Стоит одного запуска при реализации.

**Последствия пустого старта:**

| Что | Как будет |
|---|---|
| Рост орды | Его даёт только `airship_hull_1`: +10 за ход, порог 20 **[игра]**. Строку нельзя обнулять, иначе `hull_2` с ценой 2 очка не построить |
| Наём | В армии Малакая остаются горняки из `hull_1`. Гномьи воины исчезают вместе с `barracks_1`, пока их не построить снова. Стартовые отряды остаются |
| `primary_slot_building_building_level_requirement` | Значение 0 у `barracks_1`, `crew_weapons_1`, `beer_hall_1`: их можно строить до барки. Поднять до 1, тогда всё требует `hull_2`. Считаю поле от нуля, это **вывод** из `docs/research/spirit-of-grungni-buildings.md` |
| `wh3_dlc25_spirit_of_grungni.lua` | Запоминает CQI войска, а он не меняется **[игра]**. Новая кампания начинается раньше, чем скрипт что-то запомнит |
| Задания | «Улучшить корпус» просит `hull_2` или `hull_3`, цель победы просит `hull_4`. Обе совпадают с новым порядком **[данные]** |
| Вид вкладки | Карточка корпуса и карточка «построить» на следующем слоте (`p7_horde_tab_stock.png`, `p11_empty_tab.png`) **[игра]** |

## 3. Главная постройка

**`airship_hull_2`**, потому что `hull_1` убрать нельзя.

- **Стоимость сейчас:** 2500 золота, 2 очка развития, 1 ход. При росте 10 и пороге 20 на 2 очка нужно около 4 ходов (**вывод**).
- **Что ещё даёт постройка** по стоку: мстители, драконоборец, рост, резерв найма. Менять не нужно.
- **Событие:** `MilitaryForceBuildingCompleteEvent`, поля `context:building()` и `context:character()` **[игра, на чужих войсках]**. Построить `hull_2` в этом запуске не удалось: очков развития не хватило, а `DevAddDevPoint` их не прибавил.
- **`cm:add_building_to_force` события не вызывает** **[игра]**. Если постройка выдана скриптом, предмет нужно выдавать там же.
- **`mf:buildings()` в кампании нет** **[игра]**. Читать постройки можно через `common.get_context_value("CcoCampaignCharacter", cqi, "MilitaryForceContext.HordeContext.PrimarySlotContext...")`. Этот путь завязан на интерфейс, поэтому основным остаётся событие и сохранённый флаг.

### Что меняется в `tools/build.py`

- Убрать вызов `derive_skill_tree` и строки `mod_disabled`, `data/malakai_removed_skills.json` больше не нужен.
- Решить, возвращать ли `wh_main_lord_passive_deathblow` в отряд (раздел 5).
- Шесть строк вызова оставить. Проверка «expected 6 building rows» остаётся верной.
- Добавить `building_levels` в `data/db_layouts.json` и перекрыть требования трёх построек.
- Тексты `hull_1` как стапеля и `hull_2` как постройки, дающей барку.
- Своя строка `ancillary_types` и картинка.

## 4. Вызов и задания

- Пеший Малакай **не получает** вызов: включают его только шесть обнулённых строк. В легендарных битвах вызов включает `battle_set_piece_armies_effect_bundles` **[данные]**.
- Показ кнопки с обнулёнными строками проверен раньше для отряда на барке (`docs/campaign.md`). Пешком не проверял, но источник включения тот же (**вывод**).
- Задание «Призыв Духа» уже считает `thunderburner` и выдаётся на первом ходу. Пока барки нет, оно просто ждёт. Срока я в скрипте не увидел (**вывод**, в запуске не проверял). Труба есть и при пустом экипаже, поэтому после главной постройки задание выполнимо (**вывод**).
- `warpstone_bomb_6`: то же самое.
- Текст «только в легендарных битвах» на постройках остаётся.

## 5. Стоковые навыки на барке

Эффекты описаны в `docs/research/malakai-skills.md`. Новое здесь:

- **Смертельный удар вернётся и на барке.** Он дан при создании, а включение эффектом работает, даже если способности нет в строках отряда: `daring_deathblow` у отряда уже появлялся (`docs/campaign.md`). Поэтому `remove_from_unit` его не удержит (**вывод**).
- **Его можно отключить только на барке.** В `ancillary_to_effects` предмета можно добавить эффект с `disable`, который действует, пока предмет надет. В ванили есть `wh_dlc08_effect_ability_disable_deathblow` и `wh3_dlc25_effect_ability_disable_determined_deathblow`. Для `daring_deathblow` такого эффекта нет, нужен свой. Заменяющие навыки устроены так же, но с предмета это не проверено (**вывод**).
- **Числовые бонусы так не отключить.** `disable` работает только для способностей.
- **Бомба-головешка** снова требует четырёх родителей, как в стоке.
- **Не измерено на барке:** «Искусство выживания» (`general_bodyguard_size_mod`), «Неумолимость» при постоянном полёте, действие бонусов на оружие экипажа. Это уже отмечено в исследовании навыков.
- **ИИ:** тратит очки по стоку, на сокращённое дерево больше ничего не завязано (**вывод**).
- Раздел «Личные навыки убраны» в `docs/campaign.md` придётся переписать.

Цепочек столько же, сколько отсеков (5), но вариантов больше, чем уровней у стрелков и пушек. Придётся делить варианты между цепочками или добавлять уровни. Привязка не утверждена.

**Что нужно для привязки:**

1. `start` = `empty` для игрока в `data/crew_options.json`. Сейчас `M.get` берёт один `start` для всех, для ИИ нужен свой.
2. Таблица в конфиге: постройка → вариант. Новая запись без нового кода.
3. Слушатель `MilitaryForceBuildingCompleteEvent` открывает вариант, состояние хранится в сейве, как уже хранится выбор (`mtb_crew_<группа>`).
4. Выбор между открытыми вариантами остаётся вопросом `docs/design/progression-proposal.md`.
5. Текст постройки описывает открываемый вариант. Строка-заглушка эффекта без бонусов есть в ванили (`building_unlock_dummy_*`).
6. Снос постройки: решить, закрывается ли вариант.

## Как делать

1. **Данные:** шаги раздела 3.
2. **Первый тик новой кампании, только игрок:**

   ```lua
   local c = malakai
   cm:convert_force_to_type(c:military_force(), "ARMY")
   cm:convert_force_to_type(c:military_force(), "MALAKAI_BOUND_HORDE")
   ```

   Только при `cm:is_new_game()`. **Проверено в середине игры, на первом тике новой кампании не проверено.** Это первый тест реализации.

3. **Выдача:** убрать выдачу на первом тике и в `CharacterTurnStart`. На событии `hull_2` у Малакая: `cm:force_add_ancillary`, сохранить флаг, больше не выдавать.
4. **ИИ и конфедерация:** ИИ остаётся как сейчас, с постройками стока и предметом сразу. Малакай, перешедший к игроку от ИИ, уже имеет предмет.
5. **Экипаж:** старт `empty` для игрока, сток для ИИ.
6. **Навыки:** снять блокировку.
7. **Проверка в игре:**
   - новая кампания, вкладка и резерв;
   - настоящая постройка `hull_2`, предмет и пересадка;
   - бой пешком: нет вызова, стоковый отряд;
   - бой на пустой барке, сейв и загрузка, смена транспорта после движения.

## Вопросы пользователю

| Вопрос | Рекомендация |
|---|---|
| Основной слот нельзя опустошить. Подходит ли пустой стапель на месте `hull_1`? | Да. При реализации один раз попробовать скрыть его через `visible_in_ui` |
| При постройке сажать сразу или класть в резерв? | Сажать сразу, это ваши слова «посадит». Снять можно в тот же ход |
| Цена главной постройки? | Оставить 2500 золота и 2 очка: баланс вне задачи |
| ИИ-Малакай? | Стоковый старт, барка сразу, стоковый экипаж: прогрессии у ИИ нет |
| Смертельный удар на барке? | Оставить: проще и вреда нет. Отключить можно одним эффектом на предмете |
| Горняки в `hull_1` на старте? | Оставить: иначе Малакаю до `hull_2` нечего нанимать |
